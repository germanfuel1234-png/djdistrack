Introducción — ¿Qué vamos a construir?

Vamos a construir una aplicación web que visualiza en tiempo real cómo el algoritmo de Dijkstra Bidireccional encuentra el camino más corto entre dos puntos en una ciudad simulada.

🎯 Objetivo del proyecto El alumno verá en el navegador un mapa de calles. Al hacer click en dos intersecciones, la animación mostrará cómo el algoritmo "explora" las calles simultáneamente desde ambos extremos (azul desde el inicio, naranja desde el destino) hasta que se encuentran, revelando la ruta óptima en verde.

¿Por qué este proyecto es valioso?

  • Une tres áreas en un solo entregable: algoritmos, backend y frontend.
  • El resultado es visual e intuitivo — el alumno puede ver el algoritmo "pensando".
  • Es el mismo principio que usan Google Maps, Waze y GPS modernos.
  • Se puede presentar y explicar sin necesidad de conocer cada línea de código.
💡 Estrategia de enseñanza recomendada
  1. Clase 1: Conceptos del algoritmo (sin código). Diagramas en pizarrón.
  2. Clase 2: Bloques de código clave por separado. El alumno los analiza.
  3. Clase 3: Se entrega el proyecto completo. El alumno lo corre, lo explica y lo modifica.

Conceptos previos — El algoritmo de Dijkstra

📌 Para el docente Esta sección es para explicar en la pizarra ANTES de mostrar cualquier código. El alumno debe entender el "qué" antes del "cómo".

¿Qué es un grafo?

Un grafo es una estructura de datos formada por:

  • Nodos (también llamados vértices): representan puntos. En nuestro caso, intersecciones de calles.
  • Aristas (también llamadas arcos): conexiones entre nodos. En nuestro caso, calles.
  • Pesos: valor numérico de cada arista. En nuestro caso, distancia o tiempo de viaje.
     [A] ——4—— [B]
      |          |
      2          5
      |          |
     [C] ——3—— [E] ——1—— [D]
                |
                5
                |
               [G]

Grafo de ejemplo: los números son los pesos (costo de cada calle)

¿Qué hace Dijkstra?

El algoritmo de Dijkstra responde a la pregunta: "¿Cuál es el camino de menor costo entre el nodo A y el nodo X?"

Cómo funciona — paso a paso (en palabras simples)

  1. Empezamos en el nodo de origen. Su distancia es 0. Todos los demás nodos comienzan con distancia ∞.
  2. Miramos los vecinos del nodo actual y calculamos: distancia_actual + peso_arista.
  3. Si esa suma es menor que la distancia conocida del vecino, la actualizamos.
  4. Pasamos al nodo con la distancia acumulada más baja que aún no visitamos.
  5. Repetimos hasta llegar al destino.
🧩 Analogía para los alumnos Imaginen que están en el centro de una ciudad con un walkie-talkie. Mandan señales que viajan por las calles. La señal más rápida en llegar al destino habrá recorrido el camino más corto. Dijkstra simula exactamente eso: expande "olas" desde el origen.

Dijkstra Bidireccional

En vez de expandir desde un solo punto, expandimos desde ambos extremos al mismo tiempo:

  • Frente AZUL: parte del nodo inicio, avanza hacia adelante.
  • Frente NARANJA: parte del nodo destino, avanza hacia atrás.
  • Cuando ambos frentes se encuentran en un nodo → tenemos la ruta óptima.

Esto es más eficiente: en promedio explora la mitad de los nodos que Dijkstra clásico.

ConceptoDijkstra ClásicoDijkstra Bidireccional
Punto de inicioUno (origen)Dos (origen + destino)
Nodos explorados~N nodos~N/2 nodos
VelocidadNormal~2x más rápido
Usado enGrafos pequeñosGoogle Maps, GPS reales

Código de la clase Graph

Analizar con los alumnos línea a línea, preguntando "¿qué hace este método?":

class Graph:
    def __init__(self):
        self.nodes = {}   # {nodo: {}} — registra que el nodo existe
        self.edges = {}   # {nodo: {vecino: peso}} — adyacencia

    def add_node(self, value):
        if value not in self.nodes:
            self.nodes[value] = {}
            self.edges[value] = {}

    def add_edge(self, from_node, to_node, weight):
        # Auto-crea nodos si no existen
        if from_node not in self.nodes:
            self.add_node(from_node)
        if to_node not in self.nodes:
            self.add_node(to_node)
        self.edges[from_node][to_node] = weight
        self.edges[to_node][from_node] = weight  # grafo no dirigido

    def __iter__(self):
        return iter(self.nodes)  # permite: for nodo in grafo

    def __getitem__(self, node):
        return self.edges[node]  # permite: grafo["A"] → vecinos

  • ¿Qué diferencia hay entre nodes y edges?

El código del algoritmo

def dijkstra(graph, start, end):
    import heapq   # cola de prioridad (min-heap)

    # ── 1. Validaciones ───────────────────────────────────────────
    if start not in graph or end not in graph:
        return [], float('inf')

    if start == end:
        return [start], 0

    # ── 2. Inicialización ────────────────────────────────────────
    # Dict comprehension: la variable 'distances' es un diccionario
    # donde cada clave es un 'node' obtenido iterando el grafo con for,
    # y cada valor es float('infinity') — un float IEEE-754 que representa +∞.
    # Equivale a escribir: distances['A'] = inf, distances['B'] = inf, ...
    distances = {node: float('infinity') for node in graph}
    distances[start] = 0

    priority_queue = [(0, start)]   # (distancia, nodo)
    previous_nodes = {node: None for node in graph}

    # ── 3. Bucle principal ────────────────────────────────────────
    while priority_queue:
        current_distance, current_node = heapq.heappop(priority_queue)

        if current_node == end:
            break  # llegamos al destino

        if current_distance > distances[current_node]:
            continue  # registro obsoleto, lo descartamos

        for neighbor, weight in graph[current_node].items():
            distance = current_distance + weight
            if distance < distances[neighbor]:   # relajación de arista
                distances[neighbor] = distance
                previous_nodes[neighbor] = current_node
                heapq.heappush(priority_queue, (distance, neighbor))

    # ── 4. Reconstrucción del camino ──────────────────────────────
    if distances[end] == float('infinity'):
        return [], float('inf')  # no hay camino

    path = []
    node = end
    while node is not None:
        path.append(node)
        node = previous_nodes[node]
    path.reverse()  # quedó al revés (destino→origen)

    return path, distances[end]
🔍 Preguntas para el alumno
  • ¿Por qué inicializamos todas las distancias en ∞?
  • ¿Qué es heapq y por qué lo usamos en lugar de una lista normal?
  • ¿Qué significa "relajar una arista"?
  • ¿Por qué al reconstruir el camino hay que invertir la lista?

La lógica de animación

// Cada paso que devuelve el servidor tiene estas aristas nuevas:
// { new_edges_fwd: [["0x0","0x1"], ...], new_edges_bwd: [...] }

animInterval = setInterval(() => {
    const s = steps[currentStep];

    // ACUMULAR — las aristas se agregan al mapa, no se reemplazan
    (s.new_edges_fwd || []).forEach(([a, b]) => {
        litFwd[edgeKey(a, b)] = true;   // marca arista azul
    });
    (s.new_edges_bwd || []).forEach(([a, b]) => {
        litBwd[edgeKey(a, b)] = true;   // marca arista naranja
    });

    drawGraph(litFwd, litBwd, []);    // redibujar con acumulados
    currentStep++;
}, 60);  // cada 60ms → ~16 pasos por segundo
🔑 Concepto clave: acumulación vs. reemplazo En cada tick del intervalo NO borramos lo anterior. Solo agregamos las aristas nuevas. Esto crea el efecto de "mancha que crece" desde ambos extremos, igual que en el video de referencia.

Redes Informáticas — Dijkstra en la vida real

🌐 Idea central de esta sección Todo lo que construimos en este proyecto ocurre de verdad dentro de Internet cada vez que un paquete de datos viaja de una computadora a otra. Esta sección conecta el código con la realidad de las redes.

El modelo: de ciudad a red informática

La misma estructura que usamos para simular calles de una ciudad es idéntica a la que usan los routers para decidir por dónde mandar los datos:

En nuestro proyectoEn una red informática realDetalle
Nodo (intersección)Router / Switch de capa 3Dispositivo que recibe y reenvía paquetes
Arista (calle)Enlace de redCable ethernet, fibra óptica, Wi-Fi, etc.
Peso de aristaMétrica de enrutamientoPuede ser latencia, ancho de banda, costo administrativo o saltos
Ruta más cortaMejor ruta en tabla de routingEl camino que el paquete tomará para llegar a destino
Nodo inicioRouter de origenDesde donde sale el paquete
Nodo destinoRouter de destinoHacia donde debe llegar el paquete
Frente azul (exploración)Flooding de LSA (Link State Advertisements)El router inunda la red con información de sus vecinos
Ruta verde finalEntrada en tabla de routingSe guarda como: "Para llegar a X, salí por interfaz Y"

OSPF — el protocolo que usa Dijkstra en Internet

OSPF (Open Shortest Path First) es el protocolo de enrutamiento más usado en redes empresariales y de proveedores de Internet. Su nombre lo dice todo: encuentra el camino más corto primero.

Característica OSPFEquivalente en nuestro proyecto
Tipo: Link State ProtocolCada nodo conoce el grafo completo antes de correr Dijkstra
Capa OSI: Capa 3 (Red)Flask opera en Capa 7 (Aplicación) sobre TCP/IP
Métrica: costo del enlace (basada en ancho de banda)Pesos aleatorios entre 1 y 14 en nuestra grilla
Convergencia: recalcula cuando cambia la topologíaNuestro grafo es estático (no recalcula en tiempo real)
Áreas OSPF para escalarPodría simularse con subgrafos separados
📌 Actividad de pizarrón — Capa OSI y nuestro proyecto Dibujar la pila de 7 capas OSI. Pedir a los alumnos que ubiquen en qué capa opera cada componente del proyecto:
  • El cable de red de la computadora → Capa 1 (Física)
  • La dirección IP 127.0.0.1 → Capa 3 (Red)
  • El puerto 5000 de Flask → Capa 4 (Transporte / TCP)
  • El protocolo HTTP que usa el browser → Capa 7 (Aplicación)
  • El algoritmo Dijkstra simulado → equivale a Capa 3 en routers reales

¿Qué pasa realmente cuando accedés a 127.0.0.1:5000?

Aunque parece magia, hay toda una pila de protocolos actuando:

  NAVEGADOR
  │  Escribe: http://127.0.0.1:5000
  │
  ▼  Capa 7 — HTTP
     GET / HTTP/1.1
     Host: 127.0.0.1:5000
  │
  ▼  Capa 4 — TCP
     Establece conexión al puerto 5000
     Three-way handshake: SYN → SYN-ACK → ACK

Enrutamiento estático vs. dinámico

EstáticoDinámico (OSPF/RIP)
¿Quién configura las rutas?El administrador de red, a manoEl protocolo, automáticamente
¿Se adapta a fallos?No — si cae un enlace, no recalculaSí — recalcula la ruta en segundos
¿Usa Dijkstra?NoSí (OSPF usa Dijkstra internamente)
Nuestro proyecto simula…✅ Sí (grafo fijo)❌ No (no hay recálculo dinámico)
Uso típicoRedes pequeñas / ramas simplesRedes empresariales / ISPs

Métricas de enrutamiento — ¿qué puede representar el peso?

En nuestro proyecto los pesos son números aleatorios. En una red real, el peso de cada enlace puede calcularse de varias formas:

MétricaQué mideProtocolo que la usa
Saltos (hops)Cantidad de routers entre origen y destinoRIP
Ancho de bandaCosto = 100 Mbps / ancho de banda del enlaceOSPF
Latencia (delay)Tiempo de propagación del enlaceEIGRP
Carga (load)Qué tan ocupado está el enlace en ese momentoEIGRP
Costo administrativoValor asignado manualmente por el adminOSPF, BGP
💡 Reflexión para el alumno En nuestro proyecto, el algoritmo siempre elige el camino de menor suma de pesos. Si esos pesos representaran la latencia de cada enlace, el resultado sería la ruta más rápida para que un paquete llegue a destino. Eso es exactamente lo que hace tu router hogareño cuando decide por dónde mandarte el video de YouTube.
